### 8. Reset (git reset)

В GitHub Desktop нет прямой кнопки «git reset», но его функция реализована через два основных действия: **«Undo Commit»** (Отменить коммит) и **«Reset to Commit»** (Сбросить к коммиту). Оба варианта работают как **git reset --mixed** — они отменяют коммит(ы), но сохраняют изменения в файлах, чтобы мы могли их переделать.

| Функция в GitHub Desktop  | Аналог в консоли Git  | Что происходит | Когда применять |
|:------------- |:---------------:| -------------:|-------------:|
| Undo Commit (Кнопка)    | git reset --mixed HEAD~1  | Отменяет последний коммит. Изменения из этого коммита возвращаются в раздел "Changes" как незакоммиченные|Только что сделали коммит, но забыли добавить файл или ошиблись в сообщении.              |
| Reset to Commit (ПКМ в истории)| git reset --mixed <хеш_коммита> |Отменяет все коммиты от текущего состояния вплоть до выбранного вами в истории. Все изменения из этих коммитов возвращаются в раздел "Changes"| Сделали серию неудачных экспериментов (3-4 коммита) и хотите откатиться к точке, где все работало, чтобы начать заново.|


> **Обе эти функции работают только с коммитами, которые еще не были отправлены (pushed) на GitHub (в ветку main или master на сервере)**

### 9. Revert 

Так как я уже нажала кнопку Push origin, эти коммиты попали в историю на GitHub. Поэтому я не могу использовать Reset. В таком случае для безопасной отмены (не нарушающей работу моих вооброжаемых коллег) нужно использовать другую команду — Revert, которая создает новый, обратный коммит.

**Revert** — это команда Git, которая создаёт новый коммит, отменяющий изменения, внесённые каким-либо предыдущим коммитом. При этом исходный коммит не удаляется из истории, а просто добавляется новый, который делает противоположные изменения.


![IMAGE 2026-02-18 11:01:39](https://github.com/user-attachments/assets/81a83fb6-c836-48ca-a3b6-31aa4d01154a)


#### Отличие Revert от Reset

| Критерий  | Revert   | Reset|  
|:------------- |:---------------:| -------------:|
| История|	Сохраняет старые коммиты, добавляет новый |Удаляет коммиты из истории |      
| Безопасность для совместной работы |Полностью безопасен, можно пушить |Опасен, требует force push | 
|Что происходит с изменениями|Создаётся новый коммит, который отменяет старые изменения|Изменения из удалённых коммитов возвращаются в рабочую папку (--mixed) или отбрасываются (--hard)|
|Когда применять|Если коммит уже опубликован (pushed)|Только для локальных коммитов, которые ещё не на сервере|

### 10. Checkout Commit

**Checkout Commit** — это способ «заглянуть в прошлое» вашего проекта. Выбираем конкретный коммит в истории, и GitHub Desktop переключает все файлы в состояние, которое было на момент того коммита. Как будто путешествуем во времени и видим проект таким, каким он был, например, час или день назад. 

Использовать Checkout Commit, когда нужно:

* посмотреть старый код

* запустить проект в прошлом состоянии

* взять оттуда какой-то файл

Вернулись к первому коммиту. Перешли в состояние **detached HEAD** (отсоединённый указатель). Это означает, что мы больше не находимся на какой-либо ветке. Мы просто смотрим на старую версию. Можно смотреть код, запускать его, экспериментировать.

```
Нельзя (точнее, не рекомендуется) делать новые коммиты в этом состоянии.
Если всё же сделаем коммит, он будет существовать, но потом, когда переключимся
обратно на ветку, его будет трудно найти, и он может «потеряться».
```
